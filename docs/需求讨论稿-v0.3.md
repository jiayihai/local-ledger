# 本地记账 App · 需求讨论稿 v0.3

状态：历史讨论版本；最新确认见《需求讨论稿-v0.4.md》。

本轮新增确认：默认当前时间、允许补记日期、备注可选；仅人民币且精确到分；首版仅本月累计与明细，通过 Excel 后续分析；手动本地备份恢复、不使用云端；分类可停用且保留历史；首版不做专门退款功能。

## 1. 已明确的产品目标

- 安装并运行于安卓手机小米 14；离线、本地保存，当前不考虑跨设备共享。
- 记录收入与支出；大类与小类均可自行创建。
- 所有数据存入一个逻辑总账，支持统一导出和后续可视化分析。
- 首页按大类分成独立的纵向圆角矩形卡片，例如“个人”“恋爱”“收入”。
- 支出相关边框为黑色；收入相关边框为红色。不增加其他彩色。
- 苹果式简洁、圆润、有层次；希望快速启动，具体性能指标在真机验收前明确。
- 先商议需求和确认原型，再进入标准软件开发流程。

## 2. 已明确的信息结构

统一总账 → 大类 → 该大类自己的小类 → 收支记录。

示例（名称与分类仅用于演示，不是固定内置清单）：

| 大类 | 收支性质 | 示例小类 |
| --- | --- | --- |
| 个人 | 支出 | 饮食、娱乐、会员 |
| 恋爱 | 支出 | 饮食、礼物、约会 |
| 收入 | 收入 | 工资、奖金、其他收入 |

- 大类是展示与归类入口，并不是彼此隔离的数据文件或独立账本。
- 小类由各大类独立管理，可分别新增、改名、排序。个人的“饮食”和恋爱的“饮食”互不影响。
- 已确认：不用的大类或小类可以停用，保留其历史记录，新增记账时不再显示。
- 建议：停用大类时其小类一起从记账入口隐藏；历史数据仍计入对应月份总计，并可在明细和导出中查询。分类改名使用当前名称展示，ID 保持稳定。重新启用规则待确认。
- 当前按两级分类理解“大类 / 小类”；“小账”不额外增加第三层。
- 新建大类时选择“支出 / 收入”，随后自动使用对应边框；这是落实现有要求的方案建议，具体管理页面待确认。

## 3. 已明确的首页行为

- 每个大类方块显示：名称、本月累计金额、独立明细入口。
- 点击卡片主区域：进入这个大类的金额输入。
- 点击卡片内“明细”入口：查看这个大类的记录；事件独立，不触发输入金额。
- 卡片按纵向排列，圆角、简约、黑白红。具体默认排序和大类管理动作待确认。
- 不保留旧方案中的底部“记一笔”按钮。全部大类共用同一种输入界面与逻辑，通过卡片预先带入大类。
- 可另设统一“明细”页查看整个总账；底部导航暂以“记账 / 明细 / 设置”作为原型建议，未定案。

## 4. 已明确的主记账流程

首页点大类 → 输入金额 → 点“确定” → 底部弹出该大类的小类 → 点一个小类 → 保存并回首页。

- 收支性质从大类带入，记账过程中无需重复选择大类、支出或收入。
- “自动弹出”按用户之前的“点击确定后弹出”理解，以点击金额“确定”为触发点，不在每次输入数字时打断键盘。
- 点击小类即保存，不再增加一次“保存”确认。
- 正式保存的时点是选择小类时；此前只有未完成输入，不应提前进入收支统计。
- 保存后更新首页本月累计金额。若用户选择补记其他月份，当前月合计是否改变应以记录日期为准。
- 原型中保存仅为演示，不写入真实账目。

### 主流程验收草案

1. 点击“恋爱”卡片，进入金额输入页，大类已确定为“恋爱”，收支性质已确定为支出。
2. 输入 128，点击确定，仅弹出“恋爱”自己的小类。
3. 点击“礼物”，只形成一笔 128 元支出，归入“恋爱 / 礼物”，随后回首页。
4. 首页恋爱本月支出合计增加 128；个人和收入合计不变。
5. 收入路径同样操作，使用红色边框，收入合计增加。
6. 点“明细”进入对应大类的记录列表，不误触记账。

边界行为（建议，尚未确认）：金额必须大于零且最多两位小数；小类未选时取消不保存；保存防止连续点击造成重复；成功后短暂提示并允许撤销；金额上限与草稿保留规则留待确认。

## 5. 记录字段与明细

- 已明确：金额、收支性质、大类、小类、默认当前时间、可补记的日期、可选备注。
- 已明确：首版仅人民币，精确到分；无需多币种和汇率换算。
- 建议：明细支持查看、修改和删除，误删可撤销；类别改名、删除、归档与历史记录的关系需要制定规则。
- 明细首版筛选建议：日期范围、大类、小类、收入/支出。
- 已确认：首版不做专门退款功能，不提供关联原支出或自动冲减支出的流程。转账、报销等特殊流程也不列入当前已确认范围。
- 已确认：首版提供本月累计和明细，通过 Excel 后续分析；首版不加入手机内趋势图与分类占比图。

## 6. Excel 固定格式（方向已明确，具体模板待确认）

- 导出统一总账；建议支持全部或指定日期范围、指定大类的数据。
- 建议格式 .xlsx，主表“收支明细”，一笔一行，不合并明细单元格。
- 当前样表候选固定列：发生时间、收支类型、大类、小类、金额（元）、备注、记录ID、大类ID、小类ID、创建时间、更新时间。
- 金额为可计算数值，存正值，以收支类型区分；两位小数，币种为人民币 CNY。币种写入导出说明，首版不重复占用每行一列。
- 相同小类名称用大类与小类共同区分；稳定 ID 有助于分类改名后的分析关联。
- 可附“导出说明”表记录模板版本、导出时间与筛选范围；是否需要汇总表待确认。
- 不添加明细内的合计行或穿插小计，避免后续分析重复汇总。
- 表头在第一行，金额和日期使用 Excel 原生数值类型；支持筛选、冻结表头；展示色仅黑白灰与收入红色。
- 已制作样表：`../outputs/requirements-20261117/记账导出样表-v0.1.xlsx`。包含“收支明细”和“导出说明”两张表，全部为虚构示例；不是用户数据，也不代表导出模板已经获得最终确认。

## 7. 本地备份恢复

- 已确认：首版加入手动本地备份和恢复，不使用云端。
- 建议备份范围：完整记录、大类、小类、停用状态、排序与必要设置；保存稳定 ID、格式版本和创建时间。
- 建议恢复方式：导入一个备份，全量恢复到该备份时的状态；首版不做多份备份合并，避免重复记录。此恢复策略尚待用户确认。
- 建议恢复前先检查文件有效性与版本，显示备份日期和记录数量；自动保存一份当前数据备份，再由用户在 App 内确认替换。
- 建议在恢复失败时保持当前数据完整，成功时同步恢复分类、明细与累计金额。
- Excel 用于分析；完整备份用于恢复，两种文件在设置中分别展示。

## 9. 建议的默认细节（待整体审阅）

- 修改：在明细中修改金额、日期、备注及所属大类/小类，保存后重新计算受影响月份和大类的累计。
- 删除：从明细删除记录，先确认再提供短暂撤销；删除后不进入普通统计和导出。
- 新大类没有小类时：底部分类区显示“新建小类”；取消创建时不生成记账记录。
- 大类与小类名称允许修改，身份 ID 不变；现有记录随当前名称显示与导出。
- 名称去除首尾空格；同一个大类内小类不重名，不同大类可以各有“饮食”。
- 金额需大于零、最多两位小数；用户连续点击分类也只保存一次。
- 筛选与导出按实际发生日期归属，补记上个月的记录不增加本月累计。
