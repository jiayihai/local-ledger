# 本地记账 App 首版需求确认单 v1.0

整理日期：2026-11-17。

状态：历史汇总版本；最新确认稿为《首版需求确认单-v1.1.md》，新增已确认的较小“本月结余”汇总。

## 1. 产品目标与使用环境（已确认）

开发一款能安装在小米 14 上的安卓记账 App，快速记录收入、支出，并将统一明细导出为固定格式 Excel，方便后续分析。

| 项目 | 首版要求 |
| --- | --- |
| 主要设备 | 安卓小米 14；系统版本与具体安装测试环境在开发准备阶段核实 |
| 数据位置 | 手机本地；核心记账、查看与管理可离线完成 |
| 币种 | 仅人民币，精确到分 |
| 数据结构 | 一个逻辑总账，统一保存全部收入与支出 |
| 大类与小类 | 自建大类，每个大类管理自己的小类 |
| 首版分析 | 本月累计与明细；导出 Excel 后做进一步分析 |
| 备份 | 手动本地备份与恢复，不使用云端 |

## 2. 总账与分类（已确认）

统一总账 → 大类 → 大类内的小类 → 收支记录。

例如：

| 大类示例 | 收支性质 | 该大类的小类示例 |
| --- | --- | --- |
| 个人 | 支出 | 饮食、娱乐、会员 |
| 恋爱 | 支出 | 饮食、礼物、约会 |
| 收入 | 收入 | 工资、奖金、其他收入 |

- 以上名称是示例，用户可以自行创建和管理，不是固定的业务分类。
- 大类是总账里的分组与记账入口，不会各自产生隔离的数据账本。
- 每个大类的小类独立新增、改名和排序。个人的“饮食”和恋爱的“饮食”互不影响。
- 分类不再使用时可以停用：新增记账时隐藏，历史记录保留。
- 当前采用“大类 / 小类”两级，不增加第三层分类。

## 3. 首页与视觉（已确认）

采用“紧凑分区”方案：圆角长方形卡片纵向排列，名称与本月累计横向布置，每张卡片有独立的“明细”入口。

- 点卡片主区域：进入该大类的金额输入页。
- 点卡片“明细”：查看该大类的记录，不触发金额输入。
- 支出相关边框为黑色；收入相关边框为红色，收入金额用红色强调。
- 采用黑、白、红；灰度用于分隔和层次，不引入其他彩色。
- 苹果式简洁、圆润，以留白、字号、轻微层次组织信息。
- 首页保留本月收入、支出合计。
- 不单独增加底部“记一笔”按钮；各大类共用一套输入界面与记账逻辑。

视觉依据：[紧凑分区首页](design/home-compact.svg)。数字均为示例，不应带入正式安装后的真实数据。

## 4. 页面安排（已确认三页结构）

底部为“记账 / 明细 / 设置”三页。分类管理、导出与备份恢复放入设置。

| 页面或弹层 | 职责 |
| --- | --- |
| 记账 | 本月收支合计，大类卡片及对应明细入口 |
| 金额输入 | 大类已带入；输入金额，默认当前日期时间，允许补记日期和填写可选备注 |
| 小类选择弹层 | 确定金额后从底部出现，只展示当前大类可用的小类 |
| 明细 | 查看全总账或某大类记录；修改、删除与撤销 |
| 设置 | 分类管理、导出 Excel、备份到本地、恢复本地备份 |
| 分类管理 | 新增大类和小类、小类改名与排序、分类停用；其他管理细节见第 10 节 |
| 导出 | 按固定样表导出总账明细；范围选择细节见第 10 节 |
| 本地备份恢复 | 保存完整备份，按确认的恢复流程全量恢复 |

管理、编辑、筛选、导出等二级页面将在交互设计阶段按本清单细化，不改变已选三页结构。

## 5. 记账主流程（已确认）

首页点大类 → 输入金额 → 点“确定” → 底部弹出该大类的小类 → 点一个小类 → 保存并回首页。

例如：恋爱 → 128 元 → 确定 → 礼物 → 保存一笔“支出 / 恋爱 / 礼物 / 128.00”。

- 收支性质由大类带入，无需逐笔重新选择。
- 点金额“确定”后自动出现小类选择，不在输入每个数字时弹出。
- 点小类即保存，不增加第二次“保存”操作。
- 正式记录在点选小类时形成，首页与明细随之更新。
- 默认记录当前时间，允许补记日期，备注可选。

流程依据：[主记账流程图](design/category-entry-flow.svg)。其中旧版卡片外观不作为视觉定稿依据。

## 6. 记录与明细（已确认）

- 核心字段：金额、收支类型、大类、小类、发生时间、可选备注。
- 系统记录稳定记录 ID、分类 ID、创建时间和更新时间，支撑导出与数据关联。
- 可修改金额、日期、备注及所属大类、小类。
- 删除前确认，并提供短暂撤销。
- 本月累计以记录发生日期的所属月份为依据，补记日期与实际录入时间分开理解。
- 首版提供明细与本月累计，手机内不增加月度趋势或分类占比图。

## 7. Excel 导出（已采用现有样表）

采用[记账导出样表 v0.1](../outputs/requirements-20261117/记账导出样表-v0.1.xlsx)作为首版固定格式。样表中的六笔记录均为虚构示例。

工作表：

1. **收支明细**：第一行固定列名，一笔记录一行。
2. **导出说明**：模板版本、导出时间、币种、范围和字段规则等说明。

列名与顺序固定为：

| 顺序 | 列名 | 数据含义 |
| --- | --- | --- |
| 1 | 发生时间 | 用户指定的发生日期时间，默认当前时间 |
| 2 | 收支类型 | 收入或支出 |
| 3 | 大类 | 导出时的大类名称 |
| 4 | 小类 | 导出时的小类名称 |
| 5 | 金额（元） | 人民币数值，正数，两位小数 |
| 6 | 备注 | 可为空的文本 |
| 7 | 记录ID | 稳定记录标识 |
| 8 | 大类ID | 稳定大类标识 |
| 9 | 小类ID | 稳定小类标识 |
| 10 | 创建时间 | 实际录入时间 |
| 11 | 更新时间 | 最近修改时间 |

格式要求：

- 文件为 `.xlsx`；金额和日期使用原生可计算、可排序的 Excel 数值。
- 不将货币符号拼进金额文本；币种在导出说明中固定为人民币 CNY。
- 明细不合并单元格，不插入合计或小计行，保留筛选与冻结表头。
- 同名小类以所属大类和稳定 ID 区分；分类改名后名称跟随更新，ID 不变。
- 停用分类的历史记录仍包含在相应导出范围内。
- 备注作为文本，不作为公式执行。
- 不另加 App 内分析图表，也不追加未经选择的 Excel 汇总页。

样表中的“示例”内容由正式导出时的真实记录及导出信息替换，不作为固定业务数据。

## 8. 本地备份与恢复（已确认）

- 支持手动备份和恢复，不使用云端。
- 恢复前先备份当前数据，再由用户在 App 内确认，全量恢复到所选备份的状态。
- 首版不合并多份备份，不做备份与当前数据的重复记录合并。
- Excel 用于分析，完整备份用于恢复，两种入口与文件用途分开。

完整备份包含记录、分类及其状态、排序和必要设置等，具体文件结构在技术设计阶段确定。

## 9. 首版范围边界

首版包括本清单中的本地记账、分类管理、明细操作、固定 Excel 导出和手动备份恢复。

以下已明确不做：跨设备共享或云同步、App 内趋势和分类图表、多币种、专门的退款关联与自动冲减流程。

支付平台自动导入、预算、共同记账、自动周期账单等未讨论功能，不自动加入本次首版范围。后续新增需求单独评估。

## 10. 建议默认规则（随本确认单一起审阅）

本节用于补齐正常操作与边界行为，尚未逐条征询，不视为用户已单独确认；最终整体确认后纳入首版基线。用户可直接指出需要改动的条目。

| 编号 | 建议规则 |
| --- | --- |
| D01 | 首次安装不带虚构账目；无大类时显示新建入口，无小类时提供新建小类入口 |
| D02 | 新建大类时选择收入或支出，决定其边框与记账类型；已有记录的大类不直接切换收支性质 |
| D03 | 大类支持改名和手动排序；小类在各自大类内排序，排序在分类管理中完成 |
| D04 | 名称去除首尾空格；大类不重名，同一大类内小类不重名，不同大类可有同名小类 |
| D05 | 停用大类时隐藏该大类及其小类的新增记账入口；历史记录仍进入对应月份总计、明细与导出，因此首页总计可能包含已隐藏大类的金额 |
| D06 | 提供重新启用分类；重新启用大类时保留各小类自身原有的启用或停用状态 |
| D07 | 金额必须大于零、最多两位小数；无效输入不保存；连续点击小类只生成一笔记录 |
| D08 | 小类未选时退出不生成正式记录；首版不持久保存未完成草稿 |
| D09 | 新建小类成功后返回小类列表，点选该小类才保存当前记录；取消新建不记账 |
| D10 | 编辑时先带出原记录；修改大类后重新选择目标大类的小类，收支类型随目标大类更新，点保存后统一生效。原分类已停用时仍可保留原归属修改金额、日期或备注，切换分类只选可用分类 |
| D11 | 修改、删除与撤销后同步重新计算受影响月份和大类的累计；删除的记录不进入普通明细、统计和 Excel 导出 |
| D12 | 删除确认后提供 5 秒撤销；备份恢复不使用单笔删除的撤销逻辑 |
| D13 | 明细按发生时间倒序展示；提供日期范围、大类、小类及收支类型筛选，日期范围包含所选开始日与结束日 |
| D14 | Excel 可导出全部记录，或按日期范围和大类选择；导出不改变手机中的记录 |
| D15 | 恢复前检查备份有效性与版本；显示备份日期和记录数量；当前数据备份失败时不进入替换步骤 |
| D16 | 恢复前生成的当前数据副本独立保留；取消或恢复失败时当前数据保持完整，成功后分类和累计金额一并恢复 |
| D17 | 常规应用升级保留本地数据；数据版本迁移在技术设计和测试中覆盖 |
| D18 | 启动直接进入记账首页，核心功能无需等待网络；建议在小米 14 正式发布包上以冷启动可操作不超过 2 秒、热恢复不超过 1 秒作为验收目标，实测后记录结果 |

上述性能数值是待整体确认的目标，不代表目前已有可安装程序或真机测量结果。

## 11. 核心验收清单

本清单与第 10 节建议规则一起完成整体确认后，作为后续开发与真机测试依据。验收使用测试数据，不使用需求原型中的虚构合计冒充真实计算结果。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 小米 14 安装与启动 | 可安装 APK；进入紧凑分区首页，底部三页可切换 |
| A02 | 首次打开 | 无虚构账目，能创建大类与小类 |
| A03 | 恋爱大类记 128 元礼物支出 | 点确定后弹出恋爱小类；点礼物后只新增一笔并回首页，累计增加 128 元 |
| A04 | 收入大类记 100 元 | 收入使用红色边框，收入累计增加 100 元，支出不变 |
| A05 | 同名小类 | 个人与恋爱各自的饮食独立管理，记录归属正确 |
| A06 | 卡片明细入口 | 进入该大类明细，不误触记账 |
| A07 | 补记上月 | 记录归入上月，不增加本月累计；创建时间仍为实际录入时间 |
| A08 | 金额输入与取消 | 空、零、负数或超过两位小数不保存；未选小类退出不生成正式记录 |
| A09 | 重复点击 | 同一次输入连续点分类，最多保存一笔 |
| A10 | 修改记录 | 金额、日期、备注与分类可修改，受影响累计同步更新，记录 ID 不变 |
| A11 | 删除与撤销 | 删除前确认；删除后累计减少；撤销后原记录和累计恢复 |
| A12 | 分类改名、排序与停用 | 名称和顺序正确更新；停用不清空历史，新增入口隐藏 |
| A13 | 统一明细与筛选 | 全总账可查；筛选结果与日期边界正确 |
| A14 | Excel 导出 | 两张工作表、11 列名称顺序、数据类型与样表一致；每笔一行，无额外合计混入 |
| A15 | 导出数据核对 | 导出笔数与收支合计和筛选范围内的手机明细一致，包含符合范围的停用分类历史 |
| A16 | 本地备份 | 完整保留记录、分类、状态、排序与设置，并可验证备份有效 |
| A17 | 全量恢复 | 先备份当前数据再确认；恢复后匹配所选备份，不与当前数据混合 |
| A18 | 恢复异常或取消 | 当前数据备份失败、文件无效、取消或恢复失败时，当前数据保持完整 |
| A19 | 离线与重启 | 离线可记账、查看、管理、导出和备份；重启 App 后已保存记录仍在 |
| A20 | 正式包与升级 | 记录启动实测结果；覆盖安装升级后已有数据保持完整 |

## 12. 确认后的开发流程

1. 完成本确认单的整体审阅，记录需求基线；新增需求再单独登记。
2. 技术方案与开发计划：安卓技术栈、存储与金额精度、导出与备份方案、工程结构、里程碑。
3. 交互与工程设计：补齐管理、编辑、筛选、导出、备份恢复页面及数据规则。
4. 开发与验证：按主记账路径优先实现，再完成管理、明细、导出和恢复。
5. 小米 14 真机验收：安装、离线、持久化、金额与月份统计、导出、备份恢复、启动体验。
6. 交付可安装 APK、源代码、构建与安装说明、验证结果。

App 正式名称与图标、技术栈和具体适配版本在后续阶段确定，不作为本轮需求确认的阻塞项。
